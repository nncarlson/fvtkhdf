# ParaView 6.2.1 selective expansion

Historical four-type results. See the [extended five-type results](results-hypertree-6.2.1.md)
for the current matrix including HyperTreeGrid.

Checked with the same installed fVTKHDF library (`7967b14`) and ParaView 6.2.1
(VTK 9.7.2) as the original baseline. These are black-box output checks; no
coverage claims are inferred from reader implementation details.

- **Dimensions:** 32 serial files covering all supported structured type/mode
  configurations in 1D and 2D, with standalone controls. Only trailing singleton
  axes were exercised: `(nx,1,1)` and `(nx,ny,1)`.
- **MPI writing:** 15 files written with four MPI ranks and read serially.
  Rank contributions are unequal, and each block has a different empty rank,
  including rank zero. Shared structured points have one writer, and dynamic
  unstructured parts grow and shrink. This does not test distributed reading.
- **Caching:** 12 representative baseline temporal files reread with
  `UseCache=1`, including standalone controls and mixed-type/mode collections,
  forward/backward time requests, geometry/data reuse, and dynamic meshes.

All 47 new fixtures passed independent HDF5 layout checks. The 12 reused cache
fixtures also passed layout revalidation. Every added geometry and point/cell
profile passed. All standalone field-data profiles passed. MB field data
remained absent, matching the original baseline. The existing standalone
RectilinearGrid Fetch-only failure was observed in 2D/3D, not in the 1D cases.
No additional MB limitation was found by this selective expansion.

The original 38-file baseline plus the 47 new files gives 85 unique fixtures;
the cache suite adds readbacks rather than new files. The full 144 ordered-pair
matrix, nontrailing singleton layouts, and distributed reading were not run.
The tables below retain the driver-generated summaries; detailed observations
and logs are regenerated by the harness.
